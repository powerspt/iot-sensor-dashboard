# 배포 방식 선택 가이드

서버 코드는 동일하고(`server/`), **공개 방법**만 두 가지 중에서 고릅니다.

| | **A. Cloudflare Tunnel** (`cloudflare/`) | **B. 단순 IP 매핑** (`direct-ip/`) | **C. 클라우드+HTTPS** (`aws-https/`) |
|---|---|---|---|
| 접속 주소 | `https://dashboard.내도메인.com` | `http://<서버IP>:8000` | `https://dashboard.내도메인.com` |
| HTTPS(암호화) | ✅ 자동 | ❌ 평문 HTTP | ✅ 자동 (Caddy·Let's Encrypt) |
| 공인 IP 필요 | **불필요** (내부망·가정집 OK) | 필요 (또는 포트포워딩) | **필요** (AWS 등 클라우드) |
| 포트 개방 | 불필요 | 8000 허용 | 80·443 허용 |
| 준비물 | 도메인 + Cloudflare 무료 계정 | 없음 | 도메인 + 클라우드 인스턴스 |
| 난이도 | 중 (터널 1회 설정) | 하 | 중 (도메인 A레코드 + 실행) |
| 권장 용도 | 내부망·집처럼 **공인 IP가 없을 때** 상시 공개 | 빠른 실습·내부 테스트·클라우드 데모 | **AWS 등 클라우드 + 도메인**으로 상시 공개 |

## 어떤 걸 골라야 하나?

- **AWS EC2 등 클라우드에 올려 바로 써보고 싶다(HTTP 테스트)** → **B (direct-ip)**. 보안 그룹에서 포트만 열면 5분 안에 접속됩니다.
- **AWS 등 클라우드 + 내 도메인으로 상시(HTTPS) 공개** → **C (aws-https)**. 공인 IP에 도메인을 붙이고 Caddy가 인증서를 자동 발급합니다. (클라우드 웹 서비스형 표준 방식)
- **학교 내부망 PC / 집 PC라 공인 IP가 없다** → **A (cloudflare)**. 서버가 밖으로 나가는 연결만 만들어 포트포워딩 없이 공개됩니다.
- **로그인(계정·비밀번호)을 인터넷에 상시 공개** → **A** 또는 **C** (둘 다 자동 HTTPS). 평문 HTTP(B)로 장기 운영하는 것은 권장하지 않습니다.

## 공통 사항

- 데이터(SQLite)는 **레포 루트의 `data/` 폴더**에 쌓입니다(볼륨). 백업은 이 폴더만 복사하면 됩니다.
- `SECRET_KEY`는 반드시 길고 랜덤한 고정값으로 — 바뀌면 모든 로그인 세션이 풀립니다.
- ESP32(장치) 쪽 설정은 [`firmware/README.md`](../firmware/README.md) 참고 — 배포 방식에 따라 `SERVER` 주소와 `USE_HTTPS` 플래그만 다릅니다.
